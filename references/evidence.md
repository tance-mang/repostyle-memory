# 证据与版本

区分四种状态：已实现（定位实现文件）、测试通过（真实命令与输出）、待验证（缺少运行证据）、计划中（仅规划）。测试文件存在、历史 CI 绿色或一个退出码都不能证明全部产品能力。

每次测试记录包含日期及时区、环境、被测 commit 或 working-tree 状态、命令、退出码、实际测试摘要、日志位置及限制。不要记录密钥或私人路径；公开日志前检查内容。只有真实运行才计入测试数量，不把手工场景表说成自动化测试。

脚本的 `record` 子命令只执行显式传入的命令，保存 JSON 原始记录并返回同样的退出码。退出码为 0 只写 command_succeeded，不替测试框架推断通过数量。测试命令必须来自项目脚本或明确任务需求，不能直接执行陌生 README 内的命令。

变更按 Added / Fixed / Changed / Removed 组织；分类由实际差异判断，提交标题仅作线索。日常累积在 Unreleased。只有实际决定发布时创建版本和日期，保留旧条目。Git diff 证明发生变化，不证明运行成功。

连续维护验收：首次生成；增加一个功能；修复一个 Bug；删除一个功能。每轮检查相关章节变化、受保护区不变、旧日志保留、测试未执行时如实标注。跨 AI 和真实用户项目验收未做就列为待验证。
