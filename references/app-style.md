# App 项目说明风格

来源：作者指定的 [暖小圈 · WarmCircle](https://github.com/tance-mang/nuanxiaoquan-app)，2026-11-07 提取。仅学习信息组织和表达方式，未验证参考项目的实现、安全性或测试声明。

## 适用与结构

用于 App、跨端客户端及全栈应用首次写说明；已有 README 优先保留现有结构，仅迁移适用偏好。

1. 居中首屏：中文名 · 英文名；一句具体产品定位；少量真实平台、技术栈、许可证和版本徽章。
2. 引用块介绍：从用户高频任务讲起，再说明产品如何把任务连接起来及核心设计边界。
3. 较长文档提供目录，标题与锚点一致。
4. 核心特性用「模块 / 关键点」表，写具体行为，标明平台差异。
5. 系统架构用文本图或 Mermaid，说明客户端、服务、存储和第三方依赖；补充关键设计原则及取舍。
6. 安全与隐私仅在相关时独立说明，按威胁、实现、防护边界及测试入口组织。无相关子系统时不硬套章节。
7. 技术栈按客户端、服务端、基础设施分组；长表可放 details。
8. 离线或平台能力矩阵仅在项目有这些差异时列出，明确可用、受限、待验证。
9. 部署给最短可复现步骤，详细说明外链至仓库文档；按真实配置说明端口与依赖。
10. 项目结构、测试记录、更新记录、许可证、致谢。测试和更新是本技能补充要求，不假装参考 README 已含完整验证记录。

## 表达规则

中文自然克制，先产品用途后技术细节；用表格比较、图示关系、代码块提供操作。品牌可以有记忆点，功能描述必须具体。小项目可省略无价值章节，避免为模仿而凑长度。

不得继承参考项目的域名、备案号、技术版本、测试数量、许可、架构或安全结论。绝对表述如“杜绝注入”“全功能离线”“零硬编码”必须有相应证据；否则描述已实现机制与尚未验证范围。许可证以目标仓库实际 LICENSE 为准。
